## 1. 从节点配置到创作入口

文旅创作者需要背景替换和图像风格化，但直接使用 ComfyUI 要理解节点、模型、LoRA、Prompt 与生成参数。我将常用配置封装为场景工作流镜像，对用户提供 **“风格选择—素材输入—结果生成”** 的操作路径：先决定创作效果，再提交素材，底层配置由模板承接。

**个人交付：独立完成 3 个、协作完成 6 个场景工作流镜像及部署说明。** 模板复用覆盖不同素材与创作任务，部署说明同时面向后续运行和场景交接。

这一层产品抽象将用户需要做的创作选择与底层节点配置分开，让模板承担重复配置，让用户保留素材与风格的选择权。

## 2. 让内测进入具体产品迭代

我负责定向招募、技术支持与回访，累计招募 **43 名垂类 KOC，个人贡献占团队同期成果 80%**。直接跟进创作过程，将反馈整理为功能与规则需求，并推进以下迭代。

| 使用问题 | 推进的产品改动 | 产品判断 |
| --- | --- | --- |
| 生成后还要找回历史成果 | 历史记录读取与持久化 | 生成结果需要成为可回看的创作资产，不能只停留在一次会话 |
| 检查图像细节不方便 | 结果点击放大预览 | 为创作者保留检查和判断生成质量的入口 |
| 参考图导入操作繁琐 | 参考图拖拽上传 | 缩短素材进入生成流程的操作路径 |
| 不同镜头需要不同长度 | 从 5 秒 / 10 秒两档扩展为 **5–15 秒逐秒可选** | 让用户按镜头选择时长，避免只按固定档位组织创作 |
| 生成费用的规则不统一 | 推动统一**积分计费标准与费用规则规范化** | 将生成选项与费用规则放在同一套产品约束下 |

此外，我设计了**生成资产对象存储冷热分级方案**，结合历史成果留存、访问需求与存储成本做取舍。

上述贡献对应需求提出、方案设计及迭代推进；工作流镜像由我独立或协作交付，平台功能由团队协作实现。

## 3. 从电影节业务机会到影视产品原型

我牵头电影节业务探索，负责合作模式设计、外部洽谈及产品规划，将平台工具、算力资源与合作方资源组织成项目方案。产品设计是这项业务责任的一部分。

围绕剧本到成片的 **8 个生产环节**，重点处理三个问题：角色与场景在多镜头间不一致、修改牵连其他素材、反复高质量生成增加成本。

| 产品机制 | 解决的问题与取舍 |
| --- | --- |
| 角色 / 场景资产复用 | 让镜头使用共同资产，减少每次重新定义人物和环境带来的偏移 |
| 镜头级编辑与首尾帧衔接 | 把创作者控制落实到镜头和衔接位置，支持局部修改 |
| **低清确认—高质量重渲染** | 先确认画面与方向，再投入高质量生成资源；保留人工判断，控制无效生成投入 |

**交付结果：产品方案、可交互原型与项目协作方案。** 这一阶段以业务探索和原型验证为交付范围。

## 4. 渠道合作与业务结果

围绕创作者社区及生态合作，我拓展 **8 条合作渠道、23 位代理**，渠道用户增长 **3 万+**，个人贡献占团队同期渠道拉新成果 **90% 以上**。通过优化渠道结构与合作条件，将阶段性获客成本控制在**预设目标的 60%**。

**统计口径：** 90% 以上指个人占团队同期渠道拉新成果的比例；成本以预设目标为比较基准。8 条渠道、23 位代理及 3 万+ 用户为最终累计口径。

## 这个案例展示什么

从场景模板到功能迭代，我将创作者使用问题落实为操作入口、生成控制和计费规则；电影节探索展示从业务机会到产品机制与原型的组织能力，渠道结果补充商业化视角。
