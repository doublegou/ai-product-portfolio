# StayWord 案例初稿

状态：基于代码和产品文案整理；项目由李适独立完成，目标用户优先级与历史决策背景待补充。

## 用户任务

候选场景是把会议、访谈或学习录音转化为可回查文本和摘要。首版案例只选有实际使用证据的一类用户，避免同时宣称覆盖所有录音需求。

任务链路：录音或导入 → 保存原音频 → 处理与状态反馈 → 时间戳转写 → 摘要 → 查找与回听。

## 关键取舍

| 取舍 | 当前实现线索 | 需要补的解释或测量 |
| --- | --- | --- |
| 端侧处理 | 两端说明均强调本地音频、转写和摘要 | 原始用户需求依据；离线条件下实际行为 |
| 小模型摘要 | iOS 与 Android 使用各自模型和运行方案 | 摘要准确性、初始化时间、设备兼容边界 |
| 重型处理调度 | iOS 有队列/检查点，Android 描述串行模型任务 | 中断后恢复范围、是否重复处理、失败提示 |
| 保留核心能力 | Android 说明模型准备失败不阻止录音与资料库 | 缺模型、空间不足等条件下的实际体验 |
| 原生系统集成 | 播放、录音、后台与系统控制 | 权限拒绝、来电、音频路由变化的测试 |

代码提供的是实现证据，不自动证明当时的用户动机或用户满意度。

## 首版展示边界

不先增加聊天、云同步或多 Agent 功能。优先把一条录音到可用结果的流程展示清楚，并用一次真实中断或失败说明产品完整性。
