# RiverSR · 全球河水锶同位素预测与应用研究

**实验室与中科院合作背景下的科研项目：将多来源观测与环境信息转成全球预测基线，验证其迁移边界，并推进生物来源研究中的应用。**

我独立完成这里展示的数据整理、特征工程、模型实验、验证与运行工程，以及应用探索。项目从 **5,600 个河水站点**出发，经历 Full50 基线、支流与区域实验，进一步推进到 **Natural90 自然环境主基线、Human17 增量价值检验和独立生物应用验证集**。

贯穿项目的工作是：**把研究需求转成可检验的假设，用对照实验决定模型、信息和计算资源投向，再把结论转成有适用条件的交付。**

## 要解决的研究需求

河水的 **⁸⁷Sr/⁸⁶Sr** 是锶同位素比值。研究者拥有有限地点的观测，希望估计未采样河流的比值，理解误差集中在哪些环境，并进一步判断这张空间基线能否用于水生生物来源研究。

我将交付拆成三个相互依赖的层次：

| 层次 | 需要完成的任务 | 如何判断有用 |
| --- | --- | --- |
| 全球预测基线 | 从观测与环境变量估计未采样河流 | 在新支流、陌生水系、空间和资料来源迁移下评价误差 |
| 信息价值与可靠性 | 判断哪些输入值得加入，哪些环境持续失败 | 同人群配对比较、三算法共同失败、环境域诊断 |
| 应用验证 | 检验河水预测能否支持生物记录与来源判断 | 独立实测水—生物数据、已知来源基准；通过后再推进迁移案例 |

不同阶段对应不同成功标准：得到一张全球图、改善预测、发现高值、找到真实来源，需要分别验证。

## 最能说明研究判断的四项工作

### 1. 让模型评估对应真实使用场景

“已有观测水系里的新支流”与“完整陌生水系”需要不同验证。Base V2 中，我定义 **221 个不依赖 Sr 响应的支流单元**，留出待测支流并剔除其下游训练站点，避免河网连接带来的信息泄漏。

在 2,577 个适用站点上，站点均值 OOF RMSE 为 **0.01334**、R² 为 **0.425**。三个支流尺度下的九套设计，在四项预设指标上均有 **9/9 优于匹配的完整水系对照**。我据此分别定义新支流与新水系的模型承诺。[支流实验](src/river_sr/training/base/v2/RESULTS.md)

### 2. 从算法比较走向失败机制与信息投入

早期 Base V3 在相同完整水系隔离验证下，RF 的 pooled RMSE 为 **0.017235**，比 XGBoost 低 **2.76%**；MAE 低 **3.95%**。RF 在 3/3 次重复、13/15 个配对任务中取得更低 RMSE，因此保留为该阶段的连续预测基线。

![早期模型比较、训练拟合与极高值外推差异](demo/assets/model-evidence.png)

图左是选型，图右是用途判断：RF 训练拟合命中全部 29 个极高值站点，但严格站点均值 OOF 为 **0/29**。修正和区域模型也未解决迁移问题，因此我继续调查输入信息，而非只扩大调参范围。

后续研究在 **5,543 个 Natural90 适用站点**上识别三算法共同失败：777 个站点在至少一种迁移方案中出现，74 个在全部五种方案中重复出现；HG4、HG6 的失败率更高。这使研究推进到**跨算法仍然存在的困难环境**。[后续共同失败记录](evaluation/later-research-records.md#2-natural90-共同失败与环境域)

Base V2、Base V3 与 Natural90 的人群和验证任务不同，上述数值分别描述各阶段成果，不组成性能增长曲线。

### 3. 用配对实验决定是否增加一层信息

Human17 检验人口、建成区、农业、灌溉、污水、采矿和坝库等代理信息在自然基线之外是否有额外价值。我在 **同一批 5,517 站点、同一测试划分**上比较 Natural90 与 Natural90 + Human17，避免把样本变化误认为新特征收益。

发现坝库特征未应用冻结的 2015 年时间规则后，修复受影响字段、重算人群，并保留其他变量和主模型不变。重分析完成 **210 个 Outer contexts、25,920 个 candidate-fold checkpoints**；仅 LightGBM × 500 km 出现实质改善，**0/3 算法通过整体增量价值标准**。

因此保留 Natural90 全球主基线，将 Human17 作为增量研究结果，不增加未经稳定收益支持的全球预测层。这个结论限定于当前全球代理变量，不等于否认局部人类活动影响。[配对结果、修复与恢复记录](evaluation/later-research-records.md#3-human17修复时间口径后重跑配对实验)

### 4. 把模型质量与应用价值分两步验证

全球河水预测完成后，还需要验证“预测水 → 实测水 → 生物记录”之间的关系，才能进入来源研究。我将应用阶段分成独立生物基准与具体迁移案例，优先整理验证数据，避免先挑一个好看的案例再反推结论。

执行记录中，扩展敏感性集合覆盖 **20 个研究、14 个流域组、175 个个体、372 次测量**；严格集合的来源集中度仍高，因此分别保留独立性层级和适用范围。目前完成的是数据整理与协议冻结，预测对照、来源评价和迁移重建仍需继续。[应用验证集与阶段状态](evaluation/later-research-records.md#4-应用验证先建立独立生物数据再评价地图)

## 模型如何训练，资源如何投入

训练采用 CPU 与 Slurm 任务编排。以 Base V3 为例，一个外层任务包含 **48 个粗筛结构 × 3 权重 × 5 内折**，再进行 **16 个结构的细化验证**，最后用选定配方拟合外层模型。两种算法、30 个外层任务，按配置推导的 Primary 预算为 **28,830 次 fit 调用**，不含部署调参、压力测试和失败重跑。

我用渐增树数、XGBoost 内层早停、候选检查点与依赖调度控制开销；任务失败时复用已完成候选。后续 Human17 重分析中，55 个任务在输出阶段失败，只恢复对应索引，保留有效计算。

[训练与资源章节](docs/technical-design.md#训练资源耗时与成本)列出资源申请、任务日志中的可测耗时、重跑边界和成本计算口径。作业时限、并发 CPU、应用计时和实际账单分别记录，避免用其中一项替代另一项。
