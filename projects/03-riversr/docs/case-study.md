# RiverSR：研究需求、交付标准与应用规划

[返回项目](../README.md) · [实验演进与结果依据](decision-timeline.md) · [训练与技术方案](technical-design.md)

## 把研究目标拆成可以验收的任务

我将 RiverSR 的使用目标定义为：帮助研究者在观测稀疏的条件下，获得河水锶同位素的空间参考，并判断这一参考能否进入自己的研究。预测值只是其中一项交付，还需要说明模型依据、迁移条件和适用范围。

这份复盘基于已有研究过程；其中“目标交付流程”和“当前需求规划”描述下一阶段设计。

| 研究任务 | 使用者需要作出的决定 | 对产品与模型的要求 |
| --- | --- | --- |
| 研究未采样河流 | 能否用现有模型提供背景估计，还是需要补充实测 | 匹配真实迁移场景的误差评价、输入支持范围与版本 |
| 研究异常高值 | 哪些河段值得进一步检查 | 在限定误报下检查召回和跨支流覆盖，不能只看平均误差 |
| 增加一组环境信息 | 新信息是否值得提取、维护并进入全球预测 | 相同人群、相同划分的配对增量比较；收益需跨条件稳定 |
| 研究生物来源 | 河水基线能否支持候选来源判断 | 独立水—生物对应证据、已知来源评价和误差传播 |

这四类任务的误判代价不同：背景估计偏差影响后续解释；高值漏检会错过研究对象；过窄的来源范围可能排除真实来源。因此，每项用途分别设定验收条件。

## 最小闭环与扩展顺序

最初优先完成的是**可信观测 → 环境输入 → 可重复模型 → 留出预测 → 使用解释**。这个闭环提供了后续比较的共同基础。

| 范围 | 为什么优先或延后 | 已形成的结果 |
| --- | --- | --- |
| 观测与特征版本 | 数据来源、空间关联或缺失处理变化，都可能改变结论 | 站点身份、来源、Full50 特征与 manifest；数据主线扩展至 5,600 站点 |
| 基线与隔离验证 | 先判断能否预测新地点，才能决定是否投入更复杂模型 | 嵌套水系验证、支流对照、RF / XGBoost 比较及固定配方压力测试 |
| 高值修正与区域能力 | 潜在价值明确，但必须改善最终任务 | 做小规模可行性检验，再扩大验证；未通过门槛的路线停止 |
| 信息扩展与可靠性 | 原信息下持续失败，促使研究转向输入与支持范围 | Natural90 共同失败研究、Human17 配对检验 |
| 生物来源应用 | 预测地图与真实来源判断之间仍有证据缺口 | 已整理独立生物基准并冻结协议；应用对照待完成 |

早期地图用于探索查询方式，模型与评估仍是优先投入。完整研究演进保存在[假设与实验记录](decision-timeline.md)，这里关注每一步为何值得做。

## 怎样把“效果更好”变成采用标准

**整体交付收益。** 修正模型既要胜过只使用基线预测的残差对照，也要改善原始模型的最终预测。曾有候选在残差信号比较中改善，却使最终误差变差，因此停止。这一双重对照防止中间指标优化替代真正的任务收益。

**场景与错误代价。** Regional V2 的高值筛查同时要求误报 ≤10%、召回 ≥60%、精确率 ≥30%，并覆盖至少 9/14 个阳性支流和 2/4 个极高值系统。覆盖门槛约束“只在少数熟悉支流有效”的候选；这些是研究阶段的准入规则，进一步应用时仍需结合实际误判代价验证。

**信息增量与维护成本。** 新增变量在同一人群和划分中比较，报告配对差值、区间及跨条件稳定性。Human17 在一个组合改善、其他组合不稳定时，我保留研究结果，不增加正式全球预测层。

**预算与停止条件。** 先检验信号，再增加校准、更强模型或新表示。候选搜索、逐级树数、内层早停与检查点为这一顺序提供工程支持。已有组合失败后，只有新的信息或可区分的新假设，才支持再次增加计算投入。[实验依据](decision-timeline.md) · [训练与成本](technical-design.md#训练资源耗时与成本)

## 数据变更怎样闭环：坝库时间规则修复

Human17 的 H13 特征应只使用符合冻结的 2015 年时间规则的坝库记录。审查发现规则未执行，涉及上游坝数量、水库面积和河段存在性；这会改变模型输入，需要重新检验增量结论。

我将变更分成四步：

1. **限定影响范围。** 修复三个 H13 变量；保留未受影响的 Human14、Sensitivity7 与 Natural90 主模型和全球图。无法连接河网的记录标记为 unsupported，不填成“没有坝库”。
2. **重新确认比较身份。** 重算样本准入与配对关系。即使人数仍为 5,517，也要验证特征值变化，不能复用旧结论。
3. **固定其他条件重分析。** 训练/测试身份、候选、种子和采用标准保持一致；配对报告差值与不确定性，避免同时改动多项因素而失去可解释性。
4. **分别处理计算与交付失败。** 仅恢复输出失败的 55 个任务，之后检查图表和校验清单。修复后仍未通过整体增量门槛，维持自然基线的采用决定。

这次变更形成了“错误输入 → 影响对象 → 配对重分析 → 采用结论”的闭环。[字段变化与完整结果](../evaluation/later-research-records.md#3-human17修复时间口径后重跑配对实验)

## 一次研究使用应拿到什么

以下是**接入真实模型的目标交付流程**。已有研究文件支持部分环节，Web 原型尚未接通真实预测；这份标准用于约束后续接入和验收。

| 使用步骤 | 应交付的内容 | 异常或不支持时怎样处理 |
| --- | --- | --- |
| 说明问题 | 待研究位置/河段、预测或来源查询任务、输入测量及单位 | 位置无法匹配或任务不受支持时，说明需要补充什么 |
| 确认输入 | 河网匹配、环境特征版本、缺失处理和使用的模型 | 区分缺失、零值与 unsupported，保留处理记录 |
| 获得结果 | 预测值、对应验证场景、支持范围；不确定性须经过验证 | 支持不足时提供解释，不能把所有可计算地点都视为可靠 |
| 核对与带走 | 结果表、地图、输入与模型版本、可重复查询标识 | 数值、颜色与图例必须来自同一输出；保存失败应可重试 |
| 进入下一项研究 | 与独立实测水或生物记录对照，决定是否继续来源分析 | 预测失败与生物对应失败分别定位，保留未通过结果 |

已有[单站评估回放](../demo/README.md#单站复核输入留出结果与使用判断)连接了真实输入、留出划分、预测与解释，可以复核研究结果；完整交互服务和外部使用效果仍按上述流程验收。

这个流程的核心验收是：**研究者能否拿到可追溯、能解释适用条件的结果，并据此决定下一步。** 单纯完成训练或生成地图，尚不能证明这一使用流程成立。

## 当前需求规划：优先消除应用链路的不确定性

| 优先级与需求 | 下一项最小验证 | 继续或停止的依据 |
| --- | --- | --- |
| P0 · 独立水预测对照 | 冻结匹配规则，在独立实测水上评价预测误差、偏差和覆盖；按研究/流域分组汇总 | 判断应用地区是否支持后续分析；集中失效时先定位匹配、覆盖或输入问题 |
| P0 · 水—生物对应 | 检查同地点水与生物记录、时间和测量对象；保留严格与扩展集合 | 若对应关系不稳定，先限定材料类型与场景，不直接用地图解释生物来源 |
| P1 · 已知来源评价 | 在前两项支持后，检查真实来源覆盖、候选范围大小及来源独立性 | 同时约束漏掉真实来源与候选范围过宽，避免只追求看起来精确的地图 |
| P1 · 真实查询接入 | 按上述交付流程接入一个有完整数据的研究案例 | 输入、模型、数值与展示可对应，结果可复现且能解释限制 |
| 条件性 · 专家模型与迁移重建 | 有新信息或独立应用证据后再扩展 | 专家模型需证明相对基线的收益；迁移案例需有连续记录、河网与独立生态证据 |

当前生物基准的扩展集合覆盖 20 个研究、14 个流域组，但严格集合高度集中，优先处理独立性和未决样本谱系问题。协议冻结时未查看预测与残差，保留其作为后续应用验证的独立性。来源范围和覆盖的数值门槛应在正式评价前结合用途冻结。[基准准备与限制](../evaluation/later-research-records.md#4-应用验证先建立独立生物数据再评价地图)

现有成果文件与待补回的关键原件集中在[成果页](../demo/README.md)，包括后期原图、模型版本和资源记录。
