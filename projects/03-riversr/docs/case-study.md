## 研究背景与交付目标

RiverSR 是实验室与中科院合作背景下的科研项目。我独立承担这里展示的数据、特征、建模、验证和运行工程，并探索成果如何进入研究使用流程。

我把使用价值定义为三个逐级成立的任务：为未采样河流提供连续估计；说明哪些环境与信息值得信任；进一步检验河水基线能否用于生物记录和来源研究。面向科研使用者，交付必须回答“这次结果适用于什么条件、哪些输入有增量价值、下一步应该怎样验证”。

项目经过 Full50 基线、支流与区域实验、Natural90 主基线、Human17 增量研究，并推进到独立生物基准准备。以下从需求、投入与验收角度复盘；具体实验过程见[假设与实验演进](decision-timeline.md)。

## 一、以最小闭环组织从 0 到 1

按交付价值复盘，项目最初需要完成的最小闭环是：**可信观测 → 一套环境输入 → 一个可重复基线 → 符合使用条件的留出验证 → 明确的结果解释**。这是对早期研究的产品化梳理，不是补造一份当时已存在的 MVP 文档。

| 首先要解决的需求 | 早期可交付范围 | 延后的能力与原因 |
| --- | --- | --- |
| 分散数据可以被同一模型使用 | 观测规范化、站点聚合、Full50、来源与版本 | 更多变量须先解决来源、空间尺度和可用范围 |
| 模型结果能够比较和重复 | 基线、冻结分组、嵌套验证、OOF、运行契约 | 不以一个较好的随机划分分数承诺全球外推 |
| 使用者知道模型能做什么 | 连续误差、尾部、站点与水系覆盖 | 高值筛查单独验收；平均误差不替代召回和误报 |
| 研究成果有应用入口 | 查询原型与交付结构探索 | 真实来源概率、迁移路径需补充独立应用验证 |

早期把复杂度集中在数据与验证，而后按新的证据扩展模型和应用。这样每次新增工作都能说明它要改变哪一个决策。

## 二、用什么指标判断项目是否在前进

科研工具的价值指标围绕预测任务与研究决策建立。任务完成、实验稳定性、数据质量和资源消耗共同决定一次迭代是否值得保留。

| 评价层 | 指标或检查 | 影响的决策 |
| --- | --- | --- |
| 数据可用性 | 站点身份、来源、重复、覆盖、缺失语义、时间与空间尺度一致性 | 哪些记录/变量进入训练，更新是否需要重分析 |
| 连续预测质量 | 同人群 OOF 的 RMSE、MAE、R²、Bias、校准 | 哪个配方适合该迁移任务 |
| 筛查可用性 | 固定误报下的召回/精确率、独立阳性支流与极高值系统覆盖 | 是否能承担高值入口，而非仅提供排序 |
| 信息增量 | 相同测试身份上的误差差值、bootstrap 区间、跨算法/迁移稳定性 | 是否值得维护新增特征与全球预测层 |
| 可靠性 | 共同失败站点、环境域与来源分布、支持范围 | 哪些结果需谨慎解释，优先补充什么信息 |
| 工程与资源 | fit 预算、作业状态、检查点复用、日志时段、分配核时与账单 | 怎样安排并行和恢复，是否继续扩大实验 |
| 应用价值 | 独立实测水—生物对照、已知来源覆盖、基准独立性 | 是否进入来源与迁移应用 |

各阶段的门槛对应各自任务。例如 Regional V2 同时要求误报 ≤10%、召回 ≥60%、精确率 ≥30%、阳性支流 ≥9/14、极高值系统 ≥2/4；不能用更高 AUROC 抵消没有覆盖新支流的问题。科研门槛也需要与未来实际使用者的误判代价继续对齐。

## 三、需求与假设决定验证方式

**新支流与完整陌生水系。** 前者可以利用大水系其他观测，后者要求跨独立水系迁移。我通过 Naive / Purged Branch / Matched Terminal 对照检验区别，并在内外层同时清除下游信息。Base V2 的结果不能直接成为 Base V3 的精度承诺。

**残差信号与最终收益。** 修正实验分别使用 BasePred-only 残差对照与 Raw Base。一个候选即使相对前者改善，如果不能改善最终预测，就停止推进修正层。这防止局部算法收益掩盖整体交付退步。

**信息使用与信息价值。** Process14 被模型使用，没有带来更好的跨支流结果；Human17 在个别迁移单元改善，没有达到整体稳定增量标准。因此，“有领域解释”与“值得进入正式预测层”通过不同证据判断。

这些选择体现了同一个做法：先写清新增能力要改善的最终任务，设计能够改变采用/停止决定的对照，再训练模型。[实验依据](decision-timeline.md)

## 四、把数据错误作为需要控制影响范围的变更

Human17 的 H13 坝库时间规则修复，是从实验到交付的一次完整变更案例。

**触发。** 数据审查发现坝库特征没有执行已冻结的 2015 cutoff。它改变了预测变量值，原模型结论需要重分析；不能只修正文档，或保留旧结果继续解释。

**范围。** 修复三个 H13 变量，保持 Human14、Sensitivity7 与 Natural90 主模型/全球图不变；无法连接的 eligible 记录保留 unsupported，不改写为零。重新计算人群，即使样本量仍是 5,517，也不能据此认为原特征值或旧结果有效。

**实验。** 在冻结的站点配对、folds、算法、候选、种子和 gate 下重新比较 M2/M3，每个比较单元执行 2,000 次 bootstrap。如此才能将结果变化归于输入修复。

**恢复。** 回报记录中 55 个任务在最终输出目录写入时失败，只恢复对应索引，保留有效计算；后续图形和 checksum 问题与科学重分析分开处理。

**决策。** 重分析仍为 0/3 算法通过整体增量标准，保留 Natural90 主基线与 Human17 研究结论，不增加正式 Natural+Human 全球预测层。Sensitivity7 的数据 QA 与未执行的模型比较分别记录。[完整变更与结果](../evaluation/later-research-records.md#3-human17修复时间口径后重跑配对实验)

## 五、怎样安排实验投入与停止条件

我采用逐步增加验证强度的顺序：先小规模检验信号，再检验操作门槛，最后检验更强模型和新的信息表示。区域路线从 85 次拟合推进到 578 次 GAM 拟合，再到 1,156 次模型拟合，每一步都对应一个新增问题。

扩大计算不是默认下一步。全球修正未改善 Raw Base、区域新特征没有增量、Human17 未通过整体 gate 后，都形成停止或收窄交付的依据。资源继续投入到能改变结论的新数据、独立验证和应用基准。

训练工程也服务这一选择：Base V3 限制候选搜索预算、逐级增加树数、在内层早停、逐候选保存检查点，任务间通过依赖调度组织。资源峰值、实际运行时间和费用分别核算；当前可验证的局部日志不外推为项目总耗时。[训练实现与成本口径](technical-design.md#训练资源耗时与成本)

## 六、把全球图转成应用，需要两层验收

### 第一层：独立生物基准

我将河水与生物记录之间的关系拆成可定位问题的链路：预测水是否接近独立实测水；实测水与同地点生物记录是否一致；预测水与生物记录是否支持稳定对应；已知来源个体能否保留在合理候选范围。

这使应用失败可以定位到水预测、记录转移或来源推断环节。基准需要独立来源与样本谱系检查，不能把来自同一研究的多次测量当成多个独立外部验证。

后续执行回报表明基准数据和协议已冻结。扩展集合覆盖 20 个研究、14 个流域组，但严格集合仍高度集中；正式预测对照尚未完成，不将准备状态写成应用验证通过。

### 第二层：具体来源与迁移案例

在基准支持后，再选择具有连续耳石记录、清晰河网与独立生态证据的案例，探索“同位素序列 → 候选河段 → 河网连接 → 可能迁移过程”。单一案例用于说明使用方式，独立基准用于建立适用性，两者承担不同任务。

现有 Web 地图是早期合成场原型，后续 Natural90 全球科研 isoscape 是另一项研究产物。Web 原型接入仍须完成查询值与颜色绑定、特征/模型版本、不确定性及不支持区域提示，不能拿它替代后续真实科研图。[应用记录](../evaluation/later-research-records.md#4-应用验证先建立独立生物数据再评价地图) · [交付说明](../demo/README.md)

## 七、当前交付与下一步顺序

当前研究链条已经包含早期基线、验证方法迭代、信息扩展、配对增量研究与应用基准准备。作品集中的本地可复核部分是早期源码与冻结产物；后续成果目前依据原始执行回报整理，完整模型与图表仍在回报指定的 HPC 目录。

下一步优先把后续 registry、模型配方、关键表图与资源账单对应到项目；应用研究先完成独立预测对照，再推进来源验证与迁移案例。原始 Direction 2 的其他设想按实际执行证据逐项管理，不能把 Natural90 的完成当成全部方案已经完成。[材料范围](../evaluation/later-research-records.md#材料范围) · [阶段规划](decision-timeline.md#下一笔投入的优先级)
