# RiverSR 研究演进与后续规划

[返回项目](../README.md) · [研究案例](case-study.md) · [技术方案](technical-design.md)

我的研究路线围绕三个问题推进：先建立可信基线，再解释迁移失败，最后确定需要补充的信息。以下按研究阶段组织；版本号代表实验任务变化，并不组成可直接比较的性能增长曲线。

## 已完成：建立基线并拆解泛化条件

| 阶段 | 要消除的不确定性 | 形成的成果与后续判断 |
| --- | --- | --- |
| Base V0 / V1 | 全局特征在空间留出与完整水系留出下表现如何 | 建立 4,485 站点 Full50；从早期验证推进到重复嵌套水系验证；单独关注高值压缩 |
| Global High-Sr Risk | 去掉坐标后是否仍能识别陌生水系中的高值 | 比较 Elastic Net 与 Probability RF；两个候选均未通过资格门槛，转向检验连续值修正 |
| High-Sr Correction | 可学习的残差能否转成对最终预测的改善 | 四个候选检出残差信号，但没有改善 Raw Base 的完整安全表现；不继续推进全量修正 |
| Base V2 | 完整水系留出是否回答了“新支流”的问题 | 建立 221 个 branch、下游剔除、三个尺度九套几何对照；确立新支流与新水系的不同适用条件 |

Base V2 的最终站点均值 OOF RMSE 为 0.0133358、R² 为 0.424667，适用于 2,577 个 branch-eligible 站点。全水系压力测试与它的测试人群不同，不能直接据此计算升级收益。[Base V2 正式结果](../src/river_sr/training/base/v2/RESULTS.md)

## 下一阶段：Direction 2

**以下是研究方案，尚未产出对应实验结果。** 它承接当前失败诊断，将主问题改为：哪些环境信息真正具有稳定预测价值，这些关系在什么条件下能够迁移？

### 阶段目标、依赖与交付

| 阶段 | 核心实验 | 交付与进入下一阶段的条件 |
| --- | --- | --- |
| 0 · 冻结研究输入 | 冻结站点、来源、河网与历史 Full50；建立六类候选信息库，登记 spatial support、覆盖与缺失 | 候选字典、数据质量报告、分组与确认方案；先解决可用性和确认集隔离 |
| 1 · 发现稳定信息 | 比较信息模块及消融；在内层做“科学信息族 → 相关变量簇 → 单变量”筛选 | 形成具有跨折稳定性的候选 Core；每次外层测试都保持未参与该次选择 |
| 2 · 确认精简方案 | 冻结 Core、Expanded 与模型规则，用确认数据检验非劣性 | 只有同时满足站点和水系等权误差要求，才称为 Confirmed Core |
| 3 · 检验迁移范围 | 固定特征及建模规则，分别留出水文、空间、地质/气候环境和来源域 | 迁移结果矩阵、误差与支持范围；每个域使用事先确定的判定规则 |
| 4 · 诊断并重新发现 | 对失败域检查样本量、覆盖、来源混杂和输入支持，再做该域分组下的特征发现 | 判断是否能找到更稳健的统一全球特征集；需要新的确认，不能复用已看过的失败测试集宣称验证成功 |
| 5 · 条件性专家研究 | 仅在更稳健全球特征仍不足，且有关系差异证据时比较域专属结构 | 明确额外复杂度是否带来稳定增益；没有证据则不扩展专家体系 |
| 6 · 最终模型与应用 | 通过前序验证后全量拟合，输出连续预测与适用域诊断 | 冻结模型、特征、版本及不确定性；再推进真实地图接入 |

六类候选信息为：地质、水文、河网/混合、气候/地表、人类活动、空间位置。候选库的完整性与最终 Core 的精简性分别解决不同问题，不在建库阶段凭直觉确定“重要变量”。

### 信息贡献如何衡量

我将统一 RF 建模规则，用相同分组比较三种输入关系：单信息块、Spatial + Block、Expanded − Block。关键对照是：

- 超出位置代理的增量：`RMSE(Spatial) − RMSE(Spatial + Block)`。
- 在其他信息已存在时的增量：`RMSE(Expanded − Block) − RMSE(Expanded)`。

正值表示该块减少误差，同时报告绝对差、相对差以及按水文单元配对的不确定性。科学信息族与空间支持先定义，经验相关簇在训练分区内计算，防止先看全量数据再筛选带来的偏差。

原方案对强相关簇采用 `|Spearman ρ| ≥ 0.85`，对簇及变量分别进行 held-out permutation；逐步比较保留比例，每个候选重新调参。15 个外层任务中的选择频率和三次重复一致性用于判断稳定性，不能用一次 RF 重要性排序替代。

### 精简模型如何确认

原方案提出的非劣性容忍度为 `δ = min(0.0005, 0.03 × RMSE_Expanded)`，比较 `Δ = RMSE_Core − RMSE_Expanded`，按完整水系进行 2,000 次 paired bootstrap。Δ 的单侧 95% 上置信界需要在 δ 内，且站点加权与水系等权两种误差均通过。这个容忍度属于待实施的预设研究标准，并非已验证的应用容忍度。

**确认集需要先解决历史使用问题。** 原笔记设想从 5,600 站点划出约 20% 的 Terminal Confirmation Lockbox；但这些站点已经参与历史研究。重新划分只能隔离后续的 Core 选择，不能抹去历史结果对方案设计的影响。执行前应记录数据使用历史，并优先留出新增、此前未参与方法决策的独立水系作为真正的外部确认；若只能使用旧数据，就明确它是受历史使用限制的预留验证，不称为全新外部证据。

这项约束直接影响后续投入顺序：先确认可获得的独立数据和目标环境覆盖，再冻结确认方案、收集新信息、进入大规模筛选。

### 泛化失败后如何决定是否增加复杂度

Domain Generalization 固定的是 Core 与建模规则；每次留出不同域后仍需在其余数据上重新训练，不是拿一个已经见过全量数据的模型预测旧测试样本。空间方案中的距离缓冲与 Base V3 的正方形空间分块不同，需要分别命名和记录。

若迁移失败，先区分样本不足、输入超出支持范围、来源与区域混杂、特征缺口以及关系变化。先尝试寻找能跨域工作的统一信息集；仅凭某个区域分数低，不能直接推出该区域需要独立专家模型。

### 预测价值与科学解释分别验证

预测 Core 回答“哪些变量帮助预测”，关联分析回答“关系在水系内外如何变化”。原方案用预先指定的代表变量开展 GAMM / 混合模型分析，检查水系内与水系间关系、非线性曲线、空间与来源混杂、重复稳定性及多重检验。两类证据可以相互补充，但不将预测贡献解释为因果机制。
