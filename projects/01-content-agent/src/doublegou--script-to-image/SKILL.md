# 脚本转视频海报封面

让观众一眼认出讲什么、为什么值得看、是谁在讲。使用真实内容建立吸引力，把标题、人像和主题视觉设计成一张海报。

## 固定要求与可变设计

- 本次用户要求优先。默认一套三张：**3:4、4:3、16:9**，每种一张最终图片；这是跨画幅适配，不是三种选题或三套随机风格。
- 默认用本人出镜，保留参考图中的脸型、五官、发型、眼镜、自然年龄与肤色。服装是**炭灰色圆领短袖**，有真实面料质感，无额外品牌标记。姿态、表情可随内容调整，默认自然、自信，不强制惊讶表情。
- 人像特征、标题主题和当期视觉语言保持一致；配色、字体、背景、光线、构图及图形手法可随选题变化。炭灰色是衣服偏好，不等于每期都用黑色背景。海报感不等于堆霓虹、玻璃卡片和立体字。
- 当前请求没要求出图、只要求研究或优化 skill 时，完成技能工作，不擅自生成一整批示例封面。

## 1. 接续本期 post 目录，读取脚本和参考

本项目的发布素材先由 `script-to-post` 写好标题和正文。使用上一阶段明确返回的 `post/NNN/` 绝对路径，读取其中 `post.txt`；用户指定已有期号时使用该期。不要通过扫描最大编号猜本期，也不为三张图再建新编号、`covers` 或 `v1` 子目录。缺少本期文案时先按 `script-to-post` 完成文案步骤；只修改现有封面则沿用已指定目录。


阅读本期完整脚本或用户指定的摘要。已有信息直接用，不重问三种比例、语言或已知穿着。只有本期选题不清或人像资料缺失且必须本人出镜时才补问；不悄悄用其他集脚本。

读取 [设计与人像约定](references/design.md)，检查随附本地参考。区分：

- **身份参考**：原始本人照片优先；生成过的本人封面只作补充。
- **服装、版式与气氛参考**：其他封面仅提炼视觉语言；其中陌生人、文案、手机界面不是要复制的内容。
- **真实产品或品牌素材**：仅在本期确实相关时使用，不凭旧封面引入无关 logo。

本机参考保存在 `assets/private/`，清单在设计文档中。读取并查看所需图片，不能仅凭文件名判断人物。移植安装缺少这些文件时，优先使用本次附件；无合适身份图再请用户提供，不按文字描述编造“本人”。不自动将人像上传 GitHub 或其他素材库。

## 2. 提炼本期封面承诺，核实热点

在工作上下文中提取：核心对象、关键动作/差异、观众收益、脚本能证明的边界。然后按 [热点与标题](references/hotspots.md) 搜索本期相关的近期事件和讨论。先确定发布日期或时间窗口；历史视频不借今天的新闻制造旧稿已覆盖新功能的错觉。

以 `post.txt` 的发布标题和正文为主题与承诺依据，结合本期原稿提炼更短的上图文案。发布标题不必全文塞进图片，但不能另造选题、扩大收益或把正文限定删成绝对断言。继承上一阶段已核实的热点来源；只有新增或过时的事实需要再查，不能用另一个热点改掉本期承诺。只生成封面不改 `post.txt`。

用户指定的封面文字逐字保留。关键文案清单锁定后再出图：**主标题 + 可选短副标题 + 必要品牌词**。同一套三图允许换行，上图文案本身保持一致。

热点必须同时满足“有可核实来源”和“与脚本内容有直接连接”。无可靠热点就用脚本自身的有价值差异，不编“全网爆火”。发现脚本事实与现状冲突时指出具体冲突，选择不依赖争议数据的准确标题，不擅自改写讲稿。

## 3. 设计一套，分别构图

按 [设计与人像约定](references/design.md) 选一种适合本期的方向，简短告知用户标题、设计方向和热点依据，然后直接制作。

- 每张有明确主次：标题与脸是主要阅读对象；一处与内容有关的核心视觉帮助理解。需要关系图时控制分支，不把完整教程塞上封面。
- 字体处理服务中文识别。标题可有粗体、斜切、纸张肌理、轻立体等设计，但不同时堆满描边、发光、投影和裂纹。
- 为三个画幅分别安排标题、人脸、主题物位置与负空间。所有重要信息完整，不能拉伸人像、裁断标题或把一个画幅缩小塞进另一个画幅加边框。
- 默认目标尺寸为 1536×2048、2048×1536、2048×1152；这是提示目标，不是工具承诺。其他清晰的像素尺寸也可，**实际比例必须准确**，默认短边至少 1024px。

## 4. 使用出图工具，维持系列一致

出图时读取当前可用的 `imagegen` skill，遵循其实际工具接口。默认用内置 `image_gen`，不要求 API Key、不因尺寸或质量改用第三方付费服务。无可用出图工具时明确说明，不用 SVG/HTML 或纯提示词冒充图片。

按 [出图与修订](references/generation.md) 组织提示词和参考图：

1. 先生成一张主设计（默认 3:4；本次用途可改变先后）。看图检查文字、人像和构图。
2. 主设计通过自己的检查后，将它作为视觉参考，**同时保留原始人像参考**，分别生成 4:3 和 16:9；不是从一张坏脸反复衍生。无需每张都等待用户批准。
3. 每个画幅独立调用，每次只出一张完整封面，不生成三联拼图。文字和人物修改优先局部编辑，每次重申应保留的内容。
4. 默认每个画幅在首稿之后最多做两次有明确目标的修订；工具出错先检查是否已有结果，避免重复调用。不达标说明具体问题，不能无限重抽或将失败品标为完成。

## 5. 验收后交付恰好三张

对每张原尺寸图和约 320px 宽缩略预览分别检查：

- 本人相似度、炭灰短袖、自然五官与手部；无参考图陌生人混入。
- 中文逐字正确，无多余英文口号、乱码、旧标题、假 logo 或手机截图界面。
- 不看正文也能辨认核心主题；文字与脸无碰撞，背景与特效不抢主体。
- 同套三张主题、标题、人物与视觉语言一致，各画幅布局成立。
- 数据、关系图、界面暗示均有依据；示意概率不能伪装实测，封面难以解释限定时删除非必要数字。

运行只读检查：

```bash
python3 <技能目录>/scripts/check_covers.py <本套成品目录>
```

脚本需要 Pillow，检查数量、命名、可解码性、实际比例、分辨率和方向元数据；不修改图片，也不判断审美、中文或人像。不能把脚本通过等同于整体验收通过。比例异常先用出图工具修正；若仍不准确，报告实际像素与差异。只有用户明确授权其他图像处理方式时，才用相应工具做尺寸校正，不因误差小就称精确。

三张图片直接保存到本期 `post/NNN/`，文件名为 **`3-4.png`、`4-3.png`、`16-9.png`**；允许实际编码为 jpg/webp 时采用正确扩展名，不只改后缀。最终该目录恰好四个文件：`post.txt` 和三张图。检查器会要求文案存在，并允许它与图片共同存放。

创建新一期由文案 skill 负责，起始 004；封面步骤不分配编号。已存在的图片只有在用户要求修改/替换时才更新，候选与旧图临时备份放系统临时目录。续做缺失比例时只补缺项，不覆盖已认可图片。提示词、核查记录和失败候选留在工具输出或系统临时目录，不额外保存整篇脚本。

回复展示并链接三张图片，说明标题、热点来源与未验证项。按 imagegen 的交付要求在对话提供最终提示词组或链接临时提示词文件，不塞进三张成品目录。没有完成视觉检查或没有实际生成时明确说出；不承诺点击率或“保证爆款”。
