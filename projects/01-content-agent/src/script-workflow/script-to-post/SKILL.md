# 视频标题与正文

标题同时回答“讲什么”和“为什么值得看”；正文补充观看收益，而不是缩写整篇视频。

## 输入与任务范围

读取本期脚本、用户已指定的标题/平台/发布时间及同一期已有文案。已有信息直接用；只有缺少本期内容时才补问，不把旧对话的选题当新一期。默认中文，适合科技讲解视频的自然口吻。

用户只要文案时完成 `post.txt` 即可；明确要整套流程时，按 `PPT → 标题正文 → 封面` 执行。PPT 使用原 `script-to-html-slides` skill 和其输出目录，**不改 PPT 编号或存放方式**。封面使用 `script-to-image`。本 skill 不包含社交平台上传权限，不增加平台发布、自动营销或账号操作。

## 1. 提炼事实与价值

在工作上下文列出核心主题、观众最关心的问题、脚本独有的信息点、能兑现的观看收益，以及确实存在的额外资料/演示。保留必要限定，不将计划、示意、推测写成已经完成的实测或确定结论。

标题涉及“刚发布、爆火、开源、免费、最强”、版本、价格或最新变化时，联网查看原始来源和时间。热点应与脚本直接相关，不能把新闻中的新能力塞进未讲到的旧视频。普通脚本提炼无需为了热度强行搜索；需要热点但无法核实就用已确认的具体差异，说明取舍。来源记录在对话或临时笔记，不默认塞进 80～150 字正文。

## 2. 标题：一个主题、一个最强价值点

使用用户给出的方向：**核心主题/热点词 + 信息增量或观看收益**，但它是判断结构，不是固定句式。内部比较 2–3 个真正不同的切入点，默认选择一个最终标题；只有用户要求备选才额外给，备选不写入正式 `post.txt`。

- 核心关键词尽量靠前：产品、模型、公司或技术名不能藏深。
- 必须包含可辨认的信息或收益，不能只写“爆火了”“AI 圈炸了”。
- 只抓一个最强价值点，不将原理、价格、场景、教程和总结全部列进标题。
- 用具体动作或问题，例如怎么判断、为什么便宜、如何接入；少用泛泛的“深度解析”“全面解读”。
- 热点感可以有，但不默认用史上最强、颠覆、革命、炸裂。强结论必须有足够事实且符合视频覆盖范围。
- 自然、口语、顺口，不制造焦虑或假悬念。标题中的数字、分钟数、实测和教程承诺必须来自本期内容；脚本说“五分钟”不能冒充实际时长已验证。
- **替换测试**：把产品名换掉还适用于一百个对象，说明缺少本期特征。补上真正的差异，而不是再加形容词。
- 用户没有指定平台时不虚构统一字数上限。优先紧凑、容易完整读出；有具体平台要求时核实并适配。

## 3. 正文：主题 → 收益 → 可选额外价值

默认 **2～3 句话、80～150 字**，分成 1～3 个短段均可。格式不重要，信息顺序重要。

1. 第一句直接进入本期主题，不从时代背景、行业趋势或“近年来”讲起。
2. 下一句说明看完会搞清楚什么，只提 2～3 个一级价值点。不要变成章节列表或把稿子逐段压缩。
3. 有实测、Demo、从零搭建、代码、Prompt、数据或资料时，再用一句说明。没有就不硬加；“演示如何做”不自动升级成“已经实测有效”。

正文可以再次使用必要主题词，但不能原封不动复述标题；应增加标题没有提供的判断信息。删除无必要的术语、案例和功能名称：去掉它是否影响观众判断值不值得看？不影响就删。不要靠堆名词凑满 80 字。

不默认加 hashtags、emoji、求赞关注、时间戳、平台标签、营销 CTA。用户需要平台特别格式或更长描述时按当前要求覆盖默认，不将平台长篇 SEO 模板强加进通用文案。承诺“代码/Prompt 在简介”必须有可交付材料或已明确安排，不虚构链接；具体下载内容可按用户要求另外处理。

## 4. 写前自检，落盘后检查

按 [编辑检查与案例](references/editorial.md) 依次检查：事实能兑现 → 主题与收益清楚 → 本期特征具体 → 口语自然 → 标题正文互补。数值评分不能替代具体修改。

确定正式文案后，将最终标题与正文分别放临时 UTF-8 文件，使用脚本创建一期：

```bash
python3 <技能目录>/scripts/create_post.py \
  --post-root <项目的post目录> \
  --title-file <临时标题.txt> \
  --description-file <临时正文.txt>
```

脚本默认起点 004，按纯数字名称最大值加一、排他创建目录和 `post.txt`，返回这期的**绝对路径**。父目录已是 `post` 时直接用它，不生成 `post/post`。不与 PPT 的编号绑定。用 `--dry-run` 可预览下一个编号而不写文件；测试只用临时目录。

`post.txt` 固定为：

```text
标题：
<唯一的最终标题>

正文：
<最终描述>
```

只有已确定的内容才申请编号；本期已存在时直接编辑指定 `post.txt`，不要调用创建脚本。失败重试、继续封面、用户修改标题都必须使用本期已知路径，不能看到最新编号就另开一期。并发请求各自保留脚本返回路径。

```bash
python3 <技能目录>/scripts/check_post.py <本期目录>/post.txt
```

检查工具核对格式并报告字数、近似句数、重复与待审措辞；它不读脚本、不验证事实，也不判断标题好坏。默认字数以可见非空白字符计，含标点和拉丁字符；这仅是内部可复现口径，不声称等于所有平台计数。非 80～150 字或非 2～3 句会提醒，默认应修改；明确的平台/用户例外可以保留并说明。不为凑字数损害表达。

## 5. 衔接封面与交付

继续出图时把本期原始脚本上下文、最终 `post.txt`、核实过的热点依据和**刚返回的目录路径**交给封面 skill。封面可以把发布标题压缩成更短的上图文字，但不能另造选题、增加结论或反向修改 `post.txt`；三张的封面文案保持一致。

文件位置固定：`post/NNN/post.txt`、`3-4.png`、`4-3.png`、`16-9.png`。实际编码为 jpg/webp 时使用对应扩展名，不只改后缀。不创建额外 `covers/v1` 目录，不保存整篇口播稿或候选文案。

只做文案时交付最终标题、正文和 `post.txt` 链接；整套任务完成后交付同目录四个文件，并明确未完成的检查。只建立目录、只写提示词不能称整套已完成。
