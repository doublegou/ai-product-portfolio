# 编辑检查与案例

## 四项内容检查

1. **承诺核对**：主标题中的变化、教程、实测、效果和时长能否在本期找到依据？每个“更快/便宜/免费”是否保留正确对象与范围？不要用计划里的 Demo 冒充实际结果。
2. **具体性检查**：产品名替换后是否仍通用？若通用，补主题独有的动作或差异；不要靠塞全部技术术语来解决。
3. **补充性检查**：正文第一句清楚交代内容；之后只给 2～3 个观众收获。允许重复必要关键词，不允许标题整句重复。删去不影响观看决策的名词。
4. **朗读检查**：像创作者本人会说的话。不要连用“全面、深入、系统、硬核”，也不要把一串分号冒充两三句来塞入整篇稿子。

依次检查即可，不强制七轮审稿、专家评分或多代理。长度检测提醒不代表质量结论；文案符合字数但空泛，仍需修改。

## 本期特征优先

以下是基于已给 Jev 脚本的编辑示例，不是当前热点判断，也不应自动占用新一期编号：

- 虚泛：“Jev 深度解析，带你全面了解 AI 的未来”。不说明本期差异，替换产品名仍通用。
- 有特点：“Jev 不生成内容，怎么给邮件分类？”关键词靠前，抓“专门判断”的差异与实际任务；不是说这就是所有 Jev 视频唯一可用标题。
- 越界：“Jev 取代 GPT，200 封邮件零成本搞定”。原稿并未支持全面替代和零成本，不可采用。

描述示例（以视频确实演示相关流程为前提）：

> Jev 把分类、评分和是否需要处理，变成程序可以直接使用的判断结果。这期用客户邮件讲清它如何工作、为什么适合高频判断，以及怎么接入自己的流程。还会演示从准备授权到批量处理邮件的过程，帮助你把概念变成一个能运行的小工具。

这段补充了标题未交代的能力与收益，没有列 Choice、Score、Noul、Sampler、RLCD 等术语清单。若实际视频没有演示，最后一句改为真实覆盖内容；若标题已强调邮件教程，可选不同的开头以增加信息。

## 使用例外

- 用户指定长文案/特定平台：遵循要求，工具提醒可解释，不强制压回通用长度。
- 用户要求只改语气：保留事实与主要承诺，不无故换选题。
- 无额外资料：两句话即可，但应有足够具体的信息，不编“附完整代码”。
- 热点尚不确定：可写“有哪些已确认变化”或脚本确实解答的问题，不能把传闻写进结论。
- 标题后续改动：复核同目录已有封面与正文的语义一致性；只修受影响内容。
