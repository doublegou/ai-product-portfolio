# 热点与标题

## 查什么

默认“当期”指本次制作时点；用户给了发布日期，围绕它确定窗口。先看近 7 天，信息稀疏扩至 30 天；这是检索起点，不是热度定义。区分事件发生时间、页面发布时间、更新时间，搜索排序和转载日期不能证明新闻是新的。

从脚本核心名词出发，使用产品中英文名、版本、发布、实测、教程、争议等组合检索：

1. 官方发布、产品文档、原始演示：验证功能、开放范围、价格和版本。
2. 可实际访问的中文科技媒体、视频或社区讨论，再补相关英文信息：理解大家在问什么、有什么疑虑。不要只看一种平台就声称“全网”。
3. 对可能进入封面的热点钩子，至少验证事件本身；若使用“爆火 / 热议”等热度措辞，另需独立讨论或可见趋势证据。相互转载的新闻稿不算多份独立热度证据。

在工作上下文或临时文件记一个短表：候选词、原始来源链接、事件时间、脚本对应段落、可以使用的表述。没有来源的数字、排名、流量和“史上第一”不能入图。仅完成搜索不能说完成了全网热度统计。

## 怎么接回脚本

采用顺序：**脚本覆盖的主题 → 观众关心的问题 → 近期事件的真实连接 → 封面短句**。

- 新功能确实是本期所讲，可直接写功能或差异。
- 同领域热点只提供背景，可使用观众关心的问题，但不能暗示本期评测了没出现的产品。
- 传闻、泄露、价格未核实，不作为确定的封面承诺。
- “实测”“跑通”“从零做出”要求脚本确实包含相应演示或结果，不能把计划做的步骤当完成证明。
- 旧视频改封面时保留视频时点；不要把今天的发布接到旧录制里。
- 无可核实热点时继续基于脚本设计，回复说明未采用热点，不阻塞成品。
- 用户不允许联网时按脚本制作，不能暗示已核实当前事件。

## 标题示例仅说明方法

假设脚本讲的是一个将邮件做分类、评分和人工路由的判断模型：

- 可从脚本提炼：主标题“Jev：不生成，只判断”，短副标题“邮件分类怎么跑起来”。这是脚本范围内的内容表述，不代表该模型现在正流行。
- “替代所有大模型”“准确率 99%”“彻底取代人工”需要不存在于该脚本的证据，不能因为更有冲击力就写。
- 87% 这类示例概率不是准确率。若封面必须用示例数值，就在图中让示例性质清楚可见；否则优先删数字、保留“分类 / 重要程度 / 是否处理”等结果词。

内部候选可以比较准确性、辨识度和读图负担，不编数值化点击率。三张不是 A/B 测试：同一套标题保持一致，只改变断行和必要排版。
