## 从研究请求到选题交付

这次任务面向 AI 与科技内容创作，先选定 GitHub、Hacker News、V2EX 三个来源各五条；报告产生后，再回查与工作流相关的项目说明，比较“读者为什么关心”和“还需付出多少验证工作”。

| 阶段 | 实际看到的内容 | 由此作出的判断 |
| --- | --- | --- |
| 查看来源 | 三源各五条；两源缺少条目的发布时间 | 保留抓取时间，未知发布时间留空 |
| 阅读条目 | GitHub 榜单包含插件目录、科研 Skill、上下文工具 | 都是线索，需回到项目说明确认能讲什么 |
| 比较候选 | 插件主题可结合已有工作流；上下文工具需安装对照 | 优先插件主题，后者暂不做教程 |
| 交付简报 | 三个角度分别有事实、推断、待验证项 | 保留人工选择，不自动触发制作或邮件 |

## 原始字段怎样影响选题表达

下面是 [report-proxy.json](report-proxy.json) 的同一条目字段摘录，保留 null：

```json
{
  "title": "anthropics / claude-plugins-official",
  "url": "https://github.com/anthropics/claude-plugins-official",
  "publishedAt": null,
  "fetchedAt": "2026-10-16T12:45:23.028Z",
  "sourceCount": 1
}
```

这能支持“本次抓取时在 GitHub 榜单出现”；不能支持“今天新发布”或“跨平台同时热门”。数据字段会直接约束文案，而不只是留给工程排查。

## 失败与恢复

2026-10-16，直接请求三源两次全部超时。检查 macOS 系统代理后发现，系统使用 `127.0.0.1:7897`，命令行未带代理环境。将现有代理传给 Node 26 的环境代理支持后，GitHub、Hacker News、V2EX 三源各取得 5 条，共 15 条，用时 4.391 秒，退出码 0。没有修改系统网络配置。

只证明本次三源采集可用，不等于 18 个入口全部可用或长期稳定。5 条 V2EX 记录提供 publishedAt，另 10 条发布时间为空；抓取时间与发布时间分开保留。15 条未被归并，样本中没有跨源同事件正例，因此不报告归并准确率。

从真实榜单选择三个与 AI 内容工作流相关的候选，打开项目原始说明后写入 brief.md；这是本次 Agent 分析，不是 Node 自动生成的研究结论。

失败还暴露出报告持久化问题：全源失败时原程序先抛错，不保存 sourceStatus。现已改为先输出报告，再以非零状态退出；模拟 HTTP 403 的 CLI 回归验证全源失败保留空结果与逐源错误、部分失败仍保留成功条目。模拟用例与真实联网结果分开。

## 运行条件

在源码目录使用 Node 26.8.1，按本机实际配置设置 HTTP_PROXY、HTTPS_PROXY，并设置 NODE_USE_ENV_PROXY=1；然后运行原命令 `node scripts/run.mjs --sources github,hackernews,v2ex --limit 5 --format json --output <报告路径>`。旧 Node 版本不保证支持环境代理，本次没有修改工具的 Node 20 最低要求。

## 交付限制

报告交付为本地文件。当前工具没有邮件发送模块，也未建立自动定时任务。
