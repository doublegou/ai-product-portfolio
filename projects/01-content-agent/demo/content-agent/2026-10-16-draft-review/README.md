## 从用户任务到候选稿

目标读者是对观鸟好奇、缺少入门经验的人。输入不是只有产品名，而是产品功能、账号定位、平台写作规则和当前选题；输出应帮助读者理解能用它完成什么。历史运行取得草稿之后，本轮从“模型批准”继续追问“资料是否支持、读者是否会被误导”。

| 原稿中的实际表达 | 为什么需要修改 | 当前候选稿的处理 |
| --- | --- | --- |
| “散步遇到一只鸟，我用手机记下了第一次观鸟日记” | 缺少对应本人经历，标题容易被读成真实亲历 | “把散步时看到的鸟，留在自己的观察记录里” |
| “下次散步前，先看一眼地图，选一个鸟多的地方去。” | 热点提供地点线索，不能保证实际鸟况 | “热点提供地点线索，实际鸟况仍需现场观察。” |
| “每拍下一只鸟，它就会出现在「荣誉」页面里。” | 产品资料未证明相机记录与荣誉页存在这种完整映射 | 删除该承诺，按已有资料介绍最近记录 |

## 当前候选稿节选

> **把散步时看到的鸟，留在自己的观察记录里**
>
> 散步时，你会不会停下来多看一眼路边的鸟？想认识它，也想留下这次观察，可以从查资料、找地点和做记录开始。BirdTracker 把图鉴、热点地图和相机记录放在一起，为刚开始观鸟的人提供一个入口。

这段内容说明了场景与下一步动作；完整稿继续解释图鉴、热点地图、相机与回看记录。候选稿仍待最终采纳，不是已发布文章。

## 九项主张逐条复核

本轮依据 [产品记忆](../../../src/content-agent/memory/products/birdtracker.md)审核历史已通过模型审稿的草稿。审校者为当前 AI 助手，结果不是用户采纳、实机产品验收或一次新的生产生成运行。原稿和历史分数未改动。

| 主张 | 资料依据／问题 | 处理 |
| --- | --- | --- |
| 图鉴可搜索鸟种 | 产品资料明确列出搜索和条目 | 保留 |
| 物种详情含声音与习性 | 资料列出 sounds、habits 等 | 保留 |
| 热点地图和位置权限 | 资料列出 nearby hotspots、location flow | 保留 |
| 相机可保存观察记录 | 资料列出 camera flow | 保留 |
| 最近记录含鸟种、地点、日期、图片 | 资料明确列出字段 | 保留 |
| 每拍一只就进入荣誉页，累计所有记录 | 资料只说存在收藏、成就等，未证明完整映射 | 删除绝对描述 |
| 模糊照片也可用、可不填鸟种先保存 | 缺少对相机表单和识别行为的验证 | 删除推断 |
| 使用热点即可找到鸟多地点 | 地点线索不能保证实时鸟况 | 改为实际鸟况需现场观察 |
| 标题暗示一次亲历观鸟 | 没有对应本人真实事件记录 | 改为使用场景表达 |

修订稿通过字段校验和本地质量 guard。首次校验发现 guard 将“不保证…一定能看到”中的否定句也当成承诺，当前稿改用“实际鸟况仍需现场观察”；这说明关键词规则不能代替语义复核，未宣称已修复通用否定识别。

历史日志另发现一个工程问题：保存草稿后发布抛异常，saved_count 仍为 0。作品集副本把计数移动到保存成功之后，回归测试注入发布失败，验证文件仍在、saved_count=1、failed_count=1、status=partial_success。该回归是可控测试，不冒充新的平台发布尝试。

当前作品集没有配置模型 API Key，本轮未重新调用内容生产程序的模型接口；未发送、发布或操作平台页面。完整费用与主动人工时间未知，留空。


## 对候选稿的再次审查

初次修订虽然去除了四项无依据表达，仍把“未承诺上架、价格、用户规模”以及“不会描述成自动识鸟”等审校说明放进正文。它们解释了审核过程，却不帮助读者认识产品。本轮将这些说明保留在审校记录，正文聚焦查图鉴、找地点、保存与回看；保留“实际鸟况需现场观察”等会影响使用判断的提示。开头也改为使用场景，避免暗示未核实的“不填鸟种即可保存”。

本轮修改的是当前候选稿，历史原稿未变。文本、结构化草稿和网页摘录已同步；[确定性检查](structure-check.json)绑定了最新两份候选文件的指纹。该编辑修订没有新增用户反馈或模型得分。

## 改稿提示与通过条件

代码核查发现，guard 失败后的 revision_brief 会建议插入“项目代码、记忆文件和草稿文件在本地管理，模型推理调用在线 API”。这适合解释生成工具，却会把产品推广稿带向工具实现。当前 [runtime.py](../../../src/content-agent/src/create/runtime.py)已改为围绕所选产品及其资料删改，明确不插入内部实现或审校过程。

验收文档原本同时列出 overall_score >= 8.2 和 >= 8.6，已统一为实际默认门槛 8.6。新增 [四项回归](../../../src/content-agent/tests/test_review_runtime.py)检查事实 guard 的反馈与跳过模型审稿、模型 passed 不能覆盖低分、阻断项优先于高分、失败在上限内停止。内容 Agent 共 15 项测试通过，未调用真实模型。修正的是提示与判定的一致性，不将其写成生成质量提升实验。
