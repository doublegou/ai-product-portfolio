# script-workflow：把口播稿转成一套可录制、可发布的素材

我用 script-workflow 为科技讲解与产品演示制作配套素材。从一期原稿出发，按需完成演示画面、发布文案和多比例封面，并在修改时保持主题一致。

[整体产品设计](case-study.md) · [三类实际产物](../demo/script-workflow/2026-09-26-agentic-video/README.md) · [使用记录](evidence-notes.md)

## 1. 使用场景与问题定义

口播稿、演示页、标题和封面面向不同使用时刻：演示辅助观众跟上讲述，标题说明观看价值，封面在有限画幅中突出主题。直接把同一段文字复制到不同产物，不能自动满足这些要求。

从任务拆解看，创作者需要反复交接主题、讲述顺序和本期文件路径。主要风险是演示重排了口播顺序、封面承诺超出正文，以及文案调整后图片仍沿用旧标题。编号和产物位置不清楚时，还可能改错一期。

真实使用中存在两种路径：完整制作视频配套素材；已有实机演示，只生成文案和封面。2026-09-25 的 StayWord 任务明确跳过 PPT，随后我手动修改文案，再要求调整封面主副标题和海报设计。另一期视频要求改善人像清晰度、油光和设计感。因此工作流要允许部分执行和局部修订，结构检查之外还要保留视觉验收。

## 2. 产品目标与完成条件

目标是让同一期原稿可靠地传递到各类产物，并使它们能用于讲述、录屏和发布准备。

| 优先级 | 要解决的事 | 首版验收条件 |
| --- | --- | --- |
| 必须 | 演示跟随口播 | 页面和分步揭示按原稿推进；数字、限定和因果正确 |
| 必须 | 本期关系明确 | 记录 HTML 与 post 的确切路径；独立编号不会导致串期 |
| 必须 | 文案与封面一致 | 标题承诺可由原稿支持；改文案后重新核对三种封面 |
| 必须 | 产物可使用 | HTML 可独立播放；三图规格正确，文字与人像可接受 |
| 必须 | 允许单项执行 | 已有实机演示可以只做文案与封面，局部修改保留其他成果 |
| 后续验证 | 返工可定位 | 分别记录内容、视觉、播放和规格问题，以及修改时间和费用 |

录音、视频剪辑、编码和平台上传不属于首版交付。已有的 HTML 播放与文件测试只覆盖部分工程规则，视觉质量需要查看成品。

## 3. 工作流与交接

```text
同一期口播稿
  ├─ script-to-html-slides → ppt/NNN.html
  └─ script-to-post → post/MMM/post.txt
                         ↓ + 原稿、人像参考
                   script-to-image → 三比例封面
```

整套制作按演示、文案、封面执行；只需要部分素材时使用对应 Skill。HTML 与文案都直接依据原稿，封面则承接本期文案。PPT 与 post 独立编号，NNN 与 MMM 不必相同；交接使用确切路径，不猜测最大编号。

Agent 负责提炼、设计和创作；脚本负责文件创建、编号及部分格式／播放状态检查；本人编辑内容、判断表达和视觉、确认成品。人像参考用于保持身份一致。实际主题中的技术或产品数字仍须独立核实，不能将视频脚本中的数字当成本项目效果。

## 4. 方案选择与代价

| 设计问题 | 当前方案 | 可比较方案与代价 |
| --- | --- | --- |
| 如何支持不同任务 | 三个可单独使用的 Skill，以交付契约组合 | 强制一次跑全套更省选择，但不适合实机演示和局部返工；独立调用要求维护交接 |
| 如何保持主题一致 | 封面读取已确定的本期文案，HTML 直接读取原稿 | 各自产生主题容易分叉；文案变更后当前方案需复核封面 |
| 如何交付演示 | 内嵌资源的单文件 HTML，保留分步播放器 | 外置资源更方便复用和减小体积；单文件便于移动、离线播放，但需控制体积并测试交互 |
| 如何适配封面 | 三个画幅分别构图 | 一张图裁切更省步骤；独立构图保留层级与人像，但增加生成和视觉检查 |
| 如何维护不同素材 | PPT 与 post 各自编号，通过任务映射关联 | 强制同号容易理解，但不适合跳过 PPT 或单独补素材；独立编号需显式关联 |

这些代价直接进入验证：是否减少改错文件、是否保持同一期承诺、是否出现重复生成和图片规格问题。

## 5. 已观察到的需求与异常

- **部分执行有实际需求。** StayWord 实机演示已经完成，我只需要文案与封面；不能用缺少 PPT 判断该任务失败。
- **人工修改需要沿依赖传递。** 我先改 post.txt，再改封面主副标题；输入必须使用当前文案。
- **文字／文件合格不足以证明视觉合格。** 用户指出人像不清晰、泛油及设计过于朴素，说明视觉判断需要独立保留。
- **生成工具可能不严格遵守规格。** 历史聊天报告过宽版比例与短边尺寸不合格；另一轮报告修正成功。第 005 期三比例文件规格已核验，不能推广为所有历史封面均通过。
- **一期要求不自动升级为全局规则。** 另一任务明确只在本期加入现实截图，不更新 Skill。素材策略应服务当期内容，稳定规则才适合沉淀。

这些记录解释当前设计的适用性；现有证据不足以证明每条规则的首次形成时间。
