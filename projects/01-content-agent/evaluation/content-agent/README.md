# content-agent 验收与记录

状态：已完成对应真实材料的复核，结果见 [results.csv](results.csv) 和[本轮审查](../release-review.md)；采纳、效率与成本对照仍待测量。以下标准用于持续验收。对象：研究、审改和产品草稿。材料入口见[演示指南](../../demo/content-agent/README.md)，具体流程见[设计说明](../../docs/content-agent.md)。

## 合格交付

| 对象 | 人工验收要求 |
| --- | --- |
| 研究 | 说明实际采集来源、样本量和失败；建议可回查样本，样本不足不能说成充分研究 |
| 草稿 | 产品功能与产品资料一致，账号语气和场景符合要求，无虚构体验或无法支持的承诺；正文聚焦读者使用，不混入内部审校说明 |
| 审改 | 记录实际轮次、修改原因与终止状态；模型 approved 仍须人工验收 |
| 保存 | 草稿与输入、版本、日志可关联；只保存成功不等于内容可采用 |
| 发布 | 单独记录未执行、失败或成功及证据，不纳入仅草稿任务的成功条件 |
| 策略研究 | 样本、策略建议与确认后的记忆变更分别可查，与日常生产分开记录 |

## 样本与测量

先核对已有历史任务，再用一个产品生成草稿并采用真实采集不足、审稿失败或发布失败作为独立案例。后续覆盖不同产品、指定主题和研究条件。

新草稿验证用 --no-publish。分别记录采集、模型调用、审改、人工修改与重试开销；历史 189 个日志事件不作为任务分母。效果判断以人工验收为准，不能用模型分数推算采纳率。

按[共用口径](../README.md)记录。新增运行继续按[模板](../run-template.csv)记入本目录 results.csv，workflow 填 content-agent；记录关联本次输入和最终产物，保留失败与人工修订。没有实际执行时维持方法文档，不创建虚构结果。
