## 数据对象决定能做什么比较

订阅报价保留原始商品标题、平台、套餐、交付方式、期限、币种、库存、购买链接、采集时间、过期时间以及 `comparison_key` / `review_required`。商品类别用于查找；严格比较键用于同条件比较，两者承担不同任务。

API 报价以来源、模型、分组和规格区分身份，记录计费模式、现金币种 / 额度单位、输入 / 输出单价、倍率是否已应用、价格来源和监测范围。将同名模型视为同一质量服务，或将所有倍率视为相对官方定价的折扣，都会超出现有证据。

| 问题 | 当前机制 | 为什么需要 |
| --- | --- | --- |
| 订阅看起来同名但期限不同 | 严格比较按比较键、币种、交付、期限分组；至少两个来源 | 防止跨月卡 / 年卡、充值 / 成品号混比 |
| 标题有地区、首月、体验或额度条件 | 规则标记待复核，缺失信息保留未知 | 不用推测补齐关键购买条件 |
| API 分组倍率与充值额度同时出现 | 只在原站明确币种和兑换关系时换算；已含倍率不重复乘 | 避免重复折扣及现金 / 额度混淆 |
| 图片、按次和阶梯报价 | 固定单位单列；复杂阶梯保留原站入口 | 不将无法折成统一 Token 单价的服务硬排在一起 |
| 分组探测被误当成某模型能力 | 保留实际探测模型、范围、样本与来源时间 | 延迟、吞吐、可用率均不等于模型准确性或身份验证 |

[订阅规则](../src/pricemapai-web-production/src/lib/offers.ts) · [原始标题分类](../src/pricemapai-web-production/worker/classify.ts) · [API 归一](../src/pricemapai-web-production/worker/transit.ts) · [API 展示规则](../src/pricemapai-web-production/src/lib/apiTransit.ts)

当前方案没有在线调用大模型。报价金额、库存和路由需要确定、可回查的处理；未来如加入 LLM，只适合辅助提出规格候选，并接受 Schema、原文证据、单位校验和人工复核，不能直接决定可信价格。

### 一次换算怎样避免“便宜一半”的错觉

以下使用工程测试里的构造输入解释算式，**不是商家实时报价**：每百万输入 / 输出为 2 / 8 美元计价额度，分组倍率 3，充值关系为 1 CNY = 2 USD balance。原价未含倍率时，换算后为 3 / 12 元；若已含倍率，则是 1 / 4 元，不能再乘一次。没有可靠充值关系时保留额度单位，不按外汇汇率猜现金成本。

同一工作负载还应分别计输入和输出，以及缓存、阶梯和请求固定费。站点综合系数可以帮助筛选，但无法直接替代这一成本模型。[对应测试](../src/pricemapai-web-production/tests/transit.test.ts)

## 采集与写入：失败不等于商品消失

原站 HTML / 公开 JSON 经适配器解析、库存标准化和分类后写入 Supabase。CLI、管理页和定时函数复用采集逻辑；试采集不写库，实际写入受租约与数据库事务控制。

- **领取任务：**分钟 Cron 只唤醒调度，是否到期由 `next_crawl_at` 决定；租约避免两个任务重复更新，旧租约结果不能覆盖新快照。
- **完整与部分结果：**只有完整采集才能将消失商品停用；未重新看到的报价保留自己的旧时间，不能随商家心跳延长有效期。
- **失败与退避：**失败保留上次数据及错误，按来源状态退避；持续缺货不会因为一次失败被重新加速。
- **时间与库存：**未知库存、明确缺货、报价过期分别表达；每 SKU 的库存与店铺整体状态分别处理。

订阅批次最多领取 64 家、4 家并发，约 70 秒后停止领取新工作；API 批次最多 4 家、2 家并发。独立热点核验最多 6 家、3 家并发，共享来源租约。具体原站协议有不同超时，不把一个请求超时当成整个来源已失效。[采集入口](../src/pricemapai-web-production/supabase/functions/) · [事务迁移](../src/pricemapai-web-production/supabase/migrations/)

## 从统一采集到按价值分配预算

Umami 汇总最近 24 小时的商家兴趣，每 15 分钟上报一次去重会话计数，数据库通常每小时应用调度；首次新鲜报告可立即应用。不同事件的并集去重，总关注不等于分项直接相加。上报不包含会话 ID、IP、搜索原文或 API Key。

| 资源选择 | 当前策略 | 对产品的含义 |
| --- | --- | --- |
| 有明确兴趣的热门来源 | 至少 3 个会话；订阅前 20 家 / API 前 5 家可进入 10 分钟档 | 将更短更新时间优先给有需求的来源 |
| 持续价格 / 库存变化 | 结合变化次数、变化密度与同规格低价优势，分配 15 / 30 / 60 分钟档 | 变化值得跟踪，但首次入库不冒充价格变化 |
| 长期明确缺货 | 由完整成功采集确认，逐步延长至每日或每周 | 降低无效更新，同时保留恢复观察 |
| 管理者固定设置 | `adaptive_enabled=false` 不自动改档，也不进入独立热点核验 | 自动化不覆盖明确的维护判断 |
| 独立热点报价核验 | 限定商品、分组和总上限，单来源至少间隔 5 分钟 | 只刷新匹配目标的有效期，不延长全店其他旧报价 |

关注排序采用购买×3、API 外链×2、首页与详情×1。这是可调整的启发式权重，不是训练出的推荐模型。它只影响采集资源；前台价格排序不使用该权重。对抗虚假点击、长期冷门来源覆盖和调度实际收益仍需要观察。[策略与实现依据](../src/pricemapai-web-production/deploy/incremental/README.md)

### 三个时间必须分开

**采集目标间隔 ≠ 对外发布间隔 ≠ 前台数据有效期。** 最新迁移已将价格批次设为 30 分钟、热点成功后的有效期设为 45 分钟；监测字段约 2 小时同步一次，静态发布另有 5 分钟最小间隔和清单缓存。

普通订阅与 API 的过期窗口由来源间隔计算，通常为 `max(45 分钟, 3 × 来源间隔)`，并非所有记录统一 45 分钟。因此“按当前 TTL 有效”不能替代真实采集年龄；低频来源也可能有效但并不新。历史文档中 15 分钟发布 / 15 分钟热点有效期属于旧方案，当前口径以 10 月 12 日迁移为准。

## 从数据库到公开页面：一个版本完整交付

1. **数据库生成增量。** 在一个事务中比较公开字段、保存导出镜像和未确认批次；失败重发同一批次。新增、变更与删除都包含在内。
2. **稳定报价身份。** API 数组按稳定 ID 建索引，顺序或长度变化不再迫使整段数组替换。监测与价格采用不同更新节奏，减少不影响价格判断的频繁传输。
3. **串行合并与恢复。** 同步 Worker 将任务交给 Durable Object；按序合并，写入私有 R2 检查点。版本断档恢复全量；重放相同版本保持幂等。
4. **过滤与发布。** 公开字段白名单、gzip 分页、内容哈希上传；全部成功后切换静态目录，保留当前 / 上一版。发布失败不确认批次，重试继续。
5. **浏览器完整接收。** 校验清单、版本、总数和 ID，分页都成功后替换结果。失败保留旧页面并提示；旧目录过期时重新读一次清单，不回退到数据库 API。

[增量合并](../src/pricemapai-web-production/snapshot/incremental.ts) · [发布协调器](../src/pricemapai-web-production/snapshot/coordinator.ts) · [前端加载器](../src/pricemapai-web-production/src/data/snapshot.ts)

公开读路径与控制路径分离：访客只读 Static Assets；数据库及管理写入需要后端权限。管理令牌在页面内存中，刷新后重新认证；来源 URL 与跳转经过检查，遥测失败不阻断用户操作。

## 成本与容量：预算不冒充实际账单

| 项目 | 已知量或配置 | 使用方式 |
| --- | --- | --- |
| 公开快照文件 | 10 月 17 日：8,682,203 B 解压，735,986 B gzip，共 19 页 | 比较传输体积；不是浏览器下载速度或整站总流量 |
| 基础定时函数调用 | 三个分钟任务 + 每 30 分钟发布，按 30 天为 131,040 次 | 配置估算，不含手动调用与重试，不等于实际账单 |
| 数据库导出预算 | 60,000,000 B / UTC 日；按 30 天每段 1.8 GB | 包含检查点与重发；双段传输保守预留约 3.6 GB，其他流量另算 |
| 增量历史样本 | 首次 7,936,304 B；一次变化批次 590,670 B；无变化批次 118 B | 三个不同时间样本，只证明支持增量，不推算固定节省比例 |
| 超预算 | 保留待确认批次、暂停传输，次日续传 | 用数据变旧换取支出边界，前台继续保留真实时间与失效状态 |

Cloudflare、R2、Durable Object、Supabase 与统计服务器均有各自资源消耗；访客读静态资产避免了逐访问数据库查询，但不意味着任意规模零成本。实际账单和完整月度遥测尚未纳入案例。[经营与质量指标](metrics-and-experiments.md)
