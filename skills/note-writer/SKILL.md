# 小红书发布正文

把 `yt-analysis` 生成的 `analysis.md` 改写成一篇可直接发布的小红书标题与正文。这个 Skill 只写正文，不做图片规划、图片生成、外部搜索或长文中间稿。

## 输入输出契约（最高优先级）

```text
任务目录/
├── analysis.md          # 唯一内容来源
├── plan.md              # note-images 可能并行生成；不得依赖或改动
└── result/
    ├── post.md          # 本 Skill 的唯一输出
    ├── prompts/         # 不得改动
    └── *.png            # 不得改动
```

- 用户给出 `analysis.md` 时，以其父目录作为任务目录；给出任务目录时，读取其中的 `analysis.md`。
- 创建 `result/`（若尚不存在），只写 `result/post.md`。
- 若 `post.md` 已存在，直接用新版本替换，不创建 `backup`、版本化副本或其他历史文件。
- 写作完成后，任务目录只保留当前有效的 `result/post.md`；删除本 Skill 过去产生的旧正文或备份正文。
- 不创建 `meta.json`、caption 文件、长文原稿、卡片脚本或其他中间文件。

## 写作流程

1. 完整阅读 `analysis.md` 的概述、带时间戳内容与二创方向。
2. 独立提炼一个最适合小红书的切入角度、目标读者、核心承诺和内容顺序。不要读取 `plan.md` 或现有图片来决定正文。
3. 保留事实、因果、限定条件、关键例子和核心观点；允许压缩重复信息，但不得扭曲结论或补充未经支持的说法。
4. 将内容重写为可脱离来源独立发布的创作者口吻。正文不得出现“视频”“讲述者”“原视频”“原作者”“作者”“博主”“这期内容”“素材里提到”“根据字幕”“分析文件显示”等来源依附表达，也不要用“对方认为”“她提到”转述观点。直接陈述可以成立的观点；需要保留数据来源边界时，改为“在一组包含 140 个岗位的统计中”这类中性限定，不得伪装成用户亲自完成的调查。
5. 不复制长段独特措辞。改写结构、句法和表达，但不要为了显得原创而大幅改变观点。
6. 不编造第一手体验、职业身份、用户反馈、数据或案例。除非 `analysis.md` 明确记录的是用户本人经历，否则不用“我亲测”“我用了三个月”“我的客户”等话术；可改为客观陈述或面向读者的表达。
7. 生成 3–5 个内部标题候选，依据清晰度、信息价值和点击动力选择一个。标题不做虚假承诺，不使用无法证实的数字或绝对化结论。
8. 写一版紧凑、口语自然、信息密度足够的正文。篇幅随内容决定，不为凑字数扩写。先保证逻辑连续、段落完整和阅读顺畅，再做轻度自然化。
9. 按“小主题”而不是按“句子”组织正文。默认分成三个大部分：背景铺垫、核心内容、收尾。背景内部允许 1–2 个子段，核心内容中的每个并列层次或步骤各占一行，收尾通常一行。大部分之间留一行空白；同一大部分内部只换行，不插空行。
10. 完整阅读并选择性应用 [references/humanizer-zh.md](references/humanizer-zh.md)。不要机械执行“短句化”或为了节奏频繁使用句号；语义紧密的一句话保持完整，可用逗号或分号连接，但避免拖沓的超长句。阅读性、信息准确和逻辑连贯高于刻意追求人感。
11. 做一次静默自然化复查：删掉机械排比、助手口吻、泛化 CTA 和不必要的小标题。人感来自清楚的判断与自然表达，不来自一句一段、强行断句、口语表演或虚构的第一人称经历。独立短句只在确有强调价值时少量使用。
12. 最后核验标题与正文是否忠于 `analysis.md`，是否可脱离 YouTube 语境独立成立。写入前全文搜索“视频、讲述者、原作者、作者、博主、素材、字幕、这期、analysis、YouTube”等来源痕迹；只要仍有一处用于指代内容来源，就必须改写并重新检查，再写入 `result/post.md`。只有讨论这些词本身且属于正文主题时才允许保留。

## `post.md` 格式

```markdown
最终标题



背景铺垫第一段……
背景铺垫第二段……

第一层……
第二层……
第三层……
第四层……

收尾……
```

格式必须严格遵守：

- 第一行只写最终标题，不加 Markdown `#`、引号、前缀或“标题”标签。
- 标题后固定留三行空白，再开始正文。
- 正文按三个大部分排版。大部分之间固定留一行空白；同一大部分内部的子段、层次或步骤只换行，不插空行。不要把每一层都分隔成独立的大段，也不要把全文挤成一整块。
- 默认不写任何话题标签或井号标签。只有用户在当前请求中明确要求时才添加。
- 不输出标题候选、创作分析、质量评分、图片说明、来源列表或其他附加内容。

## 文风要求

- 开头尽快进入具体问题、反常识结论、读者收益或明确场景。
- 正文围绕一条主线推进；列表只在内容天然适合清单时使用。
- 使用自然的中文节奏，句子长短以表达完整为准，不为制造“活人感”硬拆句。相关分句可以用逗号或分号自然衔接；可有少量 emoji，但不要每段堆叠。
- 可以使用“你”建立交流感，也可以表达明确判断；没有真实经历时保持客观，不强行使用“我”。
- 当内容天然包含多个层次或步骤时，把它们放在同一个“核心内容”大部分中。每一层或每一步换一行，同层内容保持在这一行内；层与层之间不留空行，也不额外拆出只有一句话的小标题段。
- 避免机械的“首先、其次、最后”、空泛升华、品牌宣传腔和通用 CTA。
- 结尾可以给出具体行动建议或自然互动，不强行要求点赞、收藏、关注。

## 与图片分支的关系

`note-writer` 与 `note-images` 都直接读取同一份 `analysis.md`，可在同一轮独立产出。`note-writer` 不等待 `plan.md`，也不修改 `plan.md`；它完成后，图片仍需遵守 `note-images` 的确认闸门。
